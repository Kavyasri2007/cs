Module 1: SQL Injection (SQLi)

Variant: Authentication Bypass via Tautology

Demonstrating how direct string concatenation allows user input to break out of data literals, restructure the SQL query grammar, and authenticate without valid credentials.

1. Concept & Security Impact

SQL Injection (SQLi) occurs when untrusted user input is directly concatenated or formatted into a database command string instead of being handled as pure literal data. The database interpreter cannot distinguish between the developer's intended SQL commands and the injected metacharacters (e.g. quotes ', hyphens --, Boolean operators OR).

Impact in Authentication Bypass: An attacker can supply a Boolean tautology (such as ' OR '1'='1) that makes the query's WHERE condition universally evaluate to TRUE. Consequently, the query returns the first account in the table (frequently the administrative account), effectively granting unauthorized administrative access.

9 & 10. Viva Preparation: Questions, Answers & Alternative Mitigations

Q1: What is SQL Injection and why is string concatenation dangerous?

Answer: SQL Injection is a vulnerability where an attacker manipulates the data input stream to alter the SQL interpreter's control plane. String concatenation is dangerous because it mixes executable SQL commands with untrusted user data in the same lexical channel. When special characters (like quotes ') are concatenated, the database SQL parser mistakes user input for SQL syntax instructions.

Q2: How exactly do Parameterised Queries (Prepared Statements) prevent SQLi?

Answer: In prepared statements, the database compiles and parses the query structure before binding the data values. Placeholders (such as ? or :name) designate parameter locations. When values are subsequently supplied, the database protocol treats them exclusively as literal constants within an established parse tree. Even if a value contains quotes or SQL commands, it cannot change the syntax or logic of the query.

Q3: What other defense-in-depth mitigations should be discussed in the viva?
  • Input Allow-Lists: Validate that usernames adhere to strict formats (e.g. alphanumeric only) before reaching query logic.
  • Principle of Least Privilege: Configure the web application's database account with minimal permissions (e.g. read/write only on necessary tables, no permissions to DROP or access system catalogs).
  • Safe Error Handling: Never display raw database errors or stack traces in HTTP responses; return generic messages to avoid aiding attacker reconnaissance.
  • Object-Relational Mapping (ORM): Modern ORMs (like SQLAlchemy) use parameterized queries under the hood by default.
