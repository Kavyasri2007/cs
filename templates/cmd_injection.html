Module 2: OS Command Injection

Variant: In-band Command Injection

Demonstrating how invoking the system command shell with untrusted user input enables attackers to chain arbitrary operating-system commands and receive the output in-band.

💻 Detected Host Environment: {{ os_name }} (Shell interpreter: {% if is_windows %}cmd.exe / powershell{% else %}/bin/sh{% endif %})

1. Concept & Security Impact

OS Command Injection occurs when an application executes host operating system commands constructed from untrusted user input. When an application passes input to a shell (e.g. via shell=True in Python, system() in C, or backticks), special shell metacharacters (such as &, &&, |, ||, ;) are evaluated by the shell interpreter, enabling an attacker to append additional arbitrary commands.

In-Band vs Blind Injection: In in-band command injection, the application returns the direct standard output (stdout/stderr) of the executed command back to the user's HTTP response. In blind injection, output is not directly visible, requiring out-of-band channels or time delays (e.g. sleep) for confirmation.

Lab Safety Guarantee: All demonstration payloads in this lab use harmless diagnostic commands (e.g. whoami or printing a fixed proof banner echo [LAB-PROOF]). Destructive commands or modifications outside this isolated project are strictly prohibited.

9 & 10. Viva Preparation: Questions, Answers & Alternative Mitigations

Q1: What is the fundamental difference between OS Command Injection and SQL Injection?

Answer: While both are injection flaws involving unsafe concatenation, their execution environments and impacts differ significantly:

  • SQL Injection: Executes within the database engine's query parser, compromising database tables, records, and relational schemas.
  • OS Command Injection: Executes within the host operating system's shell interpreter (e.g. cmd.exe, bash), directly compromising the server host, underlying processes, and filesystem.
Q2: How do shell metacharacters change command interpretation?

Answer: Shell metacharacters are tokens reserved by shell interpreters to control execution flow:

  • & / ;: Sequential command separators (executes second command regardless of first command's exit code).
  • &&: Logical AND separator (executes second command only if first succeeds).
  • |: Pipe (directs stdout of first command to stdin of second).
  • `cmd` or $(cmd): Command substitution (evaluates nested command first).
Q3: Why is argument-vector execution (shell=False) superior to blacklist filtering?

Answer: Blacklist filtering is notoriously brittle because attackers can bypass filters using alternative metacharacters (newlines, null bytes, environment variables, globbing, base64 decoding). Argument-vector execution (e.g. subprocess.run(["ping", target], shell=False)) uses OS system calls (CreateProcess on Windows or execve on POSIX) directly. No shell is ever invoked to parse syntax, so metacharacters are harmlessly treated as raw string arguments.

Q4: What alternative mitigation techniques should be considered?
  • Replace Shell with Native APIs: Use native Python libraries (e.g. socket.gethostbyname, ping3) instead of executing external system binaries.
  • Strict Allow-List Validation: Reject any input that does not match a strict regex (e.g. ^[a-zA-Z0-9.-]+$).
  • Execution Timeouts: Enforce short execution deadlines (e.g. 3–5 seconds) to prevent denial of service from hanging commands.
  • Least Privilege & Sandboxing: Run the web server under a restricted OS user account with no administrative/sudo privileges, inside a container or chroot jail.
